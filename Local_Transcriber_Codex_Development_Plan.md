# Local Transcriber — план разработки в Codex

**Версия ТЗ:** 1.0  
**Дата:** 17.11.2026  
**Целевая ОС:** Windows 11 x64  
**Целевое оборудование:** Lenovo Legion Pro 5 16IAX10, Intel Core Ultra 7 255HX, NVIDIA RTX 5070 Laptop 8 GB VRAM, 32 GB RAM  
**Цель:** автономное десктопное приложение для транскрибации совещаний и вебинаров преимущественно на русском языке с временными метками, диаризацией, ручным редактированием и экспортом TXT/DOCX/PDF.

## 0. Главные решения и границы

1. **Всё распознавание и разделение говорящих выполняется локально.** Ни облачных API, ни отправки аудио, ни обязательных аккаунтов/токенов во время работы.
2. **Первоначальная подготовка проходит с интернетом**: скачивание библиотек, FFmpeg и весов. Для gated-модели pyannote требуется однократно принять условия и скачать веса с Hugging Face. После подготовки приложение работает офлайн.
3. Три отдельные задачи: **ASR** (что сказано) → **forced alignment** (когда сказаны слова) → **speaker diarization** (кто говорит). Сведение выполняет отдельный модуль.
4. Выходные документы создаются **детерминированно из проверенной и отредактированной структуры**, без дополнительной текстовой LLM. Форматирование не должно изменять смысл записи.
5. Не обещать определение реальных имён: система выдаёт `Спикер 1`, `Спикер 2` и т. п.; пользователь вручную переименовывает. Перекрытие речи и плохая запись могут привести к ошибкам.
6. **Приоритет качества и сохранности записи**, затем скорости. Запись длительностью несколько часов обрабатывается без загрузки всех моделей одновременно в VRAM.
7. MVP работает с **одним заданием за раз**; очередь нескольких файлов — второй этап.
8. Не интегрировать LM Studio, Bionic или Ollama: для точной транскрибации они не нужны. Постобработка/summary локальной LLM — необязательное отдельное расширение.

## 1. Требования и критерии готовности

### 1.1 Вход

- Пользователь выбирает файл (или перетаскивает в окно): `mp3`, `wav`, `m4a`, `flac`, `aac`, `ogg`, `mp4`, `mkv`, `mov`, `webm` и другие форматы, которые реально поддерживает включённый FFmpeg.
- Приложение проверяет существование, доступность, тип/кодек, длительность, свободное место.
- Опции: язык `Русский` (по умолчанию), `Авто`, `Английский`; диапазон количества спикеров `Авто` или точное число; режим `Качество` / `Экономия памяти`.
- Оригинал не изменяется. Для анализа создаётся отдельная временная аудиодорожка 16 kHz, mono, PCM WAV (при необходимости — чанки); оригинальная запись сохраняется для воспроизведения.

### 1.2 Выход

- Сегменты с полями: начало, конец, текст, ID спикера.
- Внутри сегментов (если успешно прошло выравнивание): слова с отдельными временными метками и флагом отсутствующего/ненадёжного выравнивания.
- Идентификаторы спикеров стабильны в рамках проекта; подписи редактируются.
- Проект сохраняется в SQLite/JSON с версией схемы; можно закрыть и открыть приложение без повторной транскрибации.
- Экспорт `txt`, `docx`, `pdf` с корректной кириллицей, временем вида `HH:MM:SS` (по настройке можно `HH:MM:SS.mmm`), заголовком и легендой участников.
- Экспорт всегда основывается на текущем **отредактированном** тексте, не на первоначальном выводе модели.
- Полностью офлайн: без сетевых запросов, регистрации, API-ключей и фоновых обновлений.

### 1.3 Редактор

- Таблица/лента расшифровки с колонками: временной интервал, спикер, текст.
- Встроенное воспроизведение, переход к фрагменту по клику на таймкод, скорость 0.75×/1×/1.25×/1.5× (если позволяет Qt Multimedia).
- Изменение текста, спикера и временных границ сегмента; объединение/разделение сегментов; отмена/повтор (минимум для изменений редактора).
- Проблемные места (неуверенное назначение спикера, неполное выравнивание, пересечения) должны обозначаться как требующие проверки, **без выдуманной числовой уверенности**.
- Автосохранение; экспорт по кнопке после просмотра.

### 1.4 Нефункциональные требования

- UI не зависает при инференсе, отмена обрабатывается корректно.
- Прогресс по фазам: извлечение аудио, распознавание, выравнивание, диаризация, сборка, экспорт. Не показывать фиктивный точный процент, если этап не предоставляет метрики.
- После сбоя временный проект восстанавливается, оригинал не удаляется.
- Безопасная обработка длинных путей/кириллицы в Windows и названий файлов с пробелами.
- В журналах — ошибки и техметрики, **без содержимого совещаний и токенов**.

## 2. Стек и архитектура

| Слой | Рекомендуемое средство | Примечание |
|---|---|---|
| UI | Python 3.11 + PySide6/Qt 6 | Windows, отделение UI от worker |
| Audio/video | FFmpeg/ffprobe | Включить офлайн-бинарники в установщик, проверить лицензию сборки |
| ASR | WhisperX + faster-whisper/CTranslate2 | Whisper Large V3 через локальный путь |
| Forced alignment | Wav2Vec2 Russian via transformers | Локальный путь к весам |
| Diarization | pyannote.audio Community-1 | Локальный pipeline из дисковой папки |
| VAD | компонент WhisperX или Silero | Проверить все связанные веса/ресурсы офлайн |
| GPU | PyTorch с поддержкой RTX 50 и совместимый CUDA runtime | Проверить реальную CUDA-доступность, не только `nvidia-smi` |
| Project store | SQLite + JSON | Данные, правки, версии схемы |
| DOCX | python-docx | Стили, пагинация, таймкоды |
| PDF | ReportLab | Кириллический TTF с соблюдением лицензии; не использовать стандартный Helvetica |
| Packaging | PyInstaller `--onedir`, Inno Setup | Сначала локальный билд, затем установщик |
| Tests | pytest, pytest-qt | Юнит, интеграционные, офлайн E2E |

**Поток данных:**

```text
File → ffprobe/FFmpeg → audio preparation/VAD
                         ↓
                 Whisper Large V3 ASR
                         ↓
                  Wav2Vec2 alignment
                         ↓
                 Pyannote diarization
                         ↓
              merge words + speakers
                         ↓
            editable Project Transcript
                         ↓
              DOCX / PDF / TXT export
```

### Организация исполнения

- Главный процесс: PySide6/UI, только быстрые операции и чтение результата.
- Отдельный **worker-процесс** для инференса, чтобы падение native CUDA/FFmpeg не убивало GUI и отмена могла остановить вычисление.
- IPC: структурированные JSON-сообщения/локальный pipe с `stage`, `status`, `progress`, `error`; **никакого локального HTTP сервера не требуется**.
- Видеоплеер остаётся в GUI; модель не держится в памяти, когда пользователь редактирует документ.
- Не запускать несколько GPU-job одновременно, пока нет реальных измерений памяти.

## 3. Модели и ссылки

### 3.1 Обязательные модели

1. **ASR:** [Systran/faster-whisper-large-v3](https://huggingface.co/Systran/faster-whisper-large-v3). Оригинальная Whisper Large V3 в формате CTranslate2. Токен не нужен для скачивания открытой модели.
2. **Forced alignment для русского:** [jonatasgrosman/wav2vec2-large-xlsr-53-russian](https://huggingface.co/jonatasgrosman/wav2vec2-large-xlsr-53-russian). Токен не нужен. Это дефолтная русская модель alignment у WhisperX.
3. **Diarization:** [pyannote/speaker-diarization-community-1](https://huggingface.co/pyannote/speaker-diarization-community-1). Для первоначального получения весов принять условия доступа и использовать токен Hugging Face; загрузка из локальной папки **без интернета** поддерживается официально.
4. **VAD:** проверить, какие локальные веса использует зафиксированная версия WhisperX (pyannote VAD либо Silero). Включить этот компонент и все его зависимости в offline manifest. Не считать его автоматически частью Community-1.

### 3.2 Альтернативы при нехватке памяти/скорости

- В интерфейсе предусмотреть необязательный профиль Whisper `medium`/`large-v3-turbo` после отдельной проверки точности на русских совещаниях; **не заменять Large V3 без сравнительного теста**.
- Основной режим ASR на GPU: сначала `float16`, `batch_size=4`; при OOM пробовать `batch_size=2`, затем `int8` (или `int8_float16`, если поддерживается используемой библиотекой).
- Alignment и diarization запускать **последовательно**, освобождая модель ASR. Если диаризация не помещается в GPU, CPU fallback с предупреждением о возможной низкой скорости.

### 3.3 Где хранить модели

```text
%LOCALAPPDATA%\LocalTranscriber\models\
  whisper-large-v3\
  wav2vec2-ru\
  pyannote-community-1\
  vad\                 # только если требуется отдельная модель/файл
```

Пути должны задаваться через конфигурацию, без жёсткой привязки к `C:\Users\...`. Запуск моделей строго по **абсолютным локальным путям**.

### 3.4 Токены

**Нужен только один токен на этапе подготовки:** Hugging Face access token типа **Read**.

1. Зарегистрировать аккаунт: https://huggingface.co/join
2. Открыть gated-модель: https://huggingface.co/pyannote/speaker-diarization-community-1
3. Принять условия доступа на странице модели.
4. Создать токен `Read`: https://huggingface.co/settings/tokens (если fine-grained, дать доступ к нужному репозиторию).
5. Скачать всю модель (не один конфигурационный файл), убедиться, что Git LFS/Xet объекты целиком присутствуют.
6. **Не хранить токен в коде, `.env`, логах и установщике.** После загрузки runtime не требует токена. Отдельный подготовительный скрипт читает временную переменную окружения.

**Не нужны:** OpenAI API key, pyannoteAI API key, токен Ollama/LM Studio. **Не использовать `precision-2`**, так как это облачный сервис, противоречащий цели.

### 3.5 Подготовка моделей online → offline

- Создать скрипт `scripts/download_models.py`, используя `huggingface_hub.snapshot_download(..., local_dir=...)` для открытых моделей и защищённого pyannote-репозитория с полученным токеном. Для pyannote допустим также официальный способ через `git lfs` + `git clone` после авторизации.
- Скачать Pyannote как **полный pipeline** и протестировать `Pipeline.from_pretrained(local_path)`.
- Скачать Wav2Vec2 с processor/tokenizer/config/weights, не только `model.safetensors`.
- Проверить загрузку WhisperModel из `models/whisper-large-v3`.
- Проверить любую дополнительную зависимость VAD/torch/torchaudio/ffmpeg.
- Сгенерировать `models-manifest.json`: модель, источник, revision/commit, список обязательных файлов, контрольные суммы, лицензия.
- В приложении сделать `Settings → Models → Verify`, показывать недостающие модели до запуска.
- На runtime задать `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1` и `HF_HUB_DISABLE_TELEMETRY=1`; в загрузчиках выставить `local_files_only=True`, где поддерживается. Для pyannote — локальный путь, не ID репозитория.
- **Проверить реальной блокировкой сети:** успешный первый запуск, ASR, alignment, diarization, экспорт, повторный запуск после перезагрузки.

## 4. Windows prerequisites и совместимость RTX 5070

Перед программированием GUI создать отдельный технологический прототип:

1. Обновить NVIDIA Studio Driver или Game Ready Driver до версии, поддерживающей RTX 5070 и выбранный CUDA stack.
2. Использовать изолированное Python 3.11 venv (или `uv`).
3. Установить CUDA-совместимые версии PyTorch из официального селектора: https://pytorch.org/get-started/locally/ . Проверить `torch.cuda.is_available()` и тестовый tensor на GPU.
4. Учесть требования текущего WhisperX к CUDA Toolkit 12.8 на Windows: https://github.com/m-bain/whisperX . Нужны совместимые CUDA/cuDNN/CTranslate2, а не произвольные самые новые версии.
5. Установить WhisperX и выполнить консольный тест на коротком локальном русскоязычном файле.
6. Создать **зафиксированный lock-файл** из проверенного набора версий; не смешивать непроверенные CUDA wheels. Версии не подбирать наугад.
7. Скачать FFmpeg с https://ffmpeg.org/download.html и проверить `ffmpeg -version`/`ffprobe -version`.

**Команды диагностики (PowerShell):**

```powershell
nvidia-smi
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
# Далее — установка проверенного CUDA/PyTorch и закреплённых зависимостей
python -c "import torch; print(torch.__version__, torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

Не начинать упаковку `.exe`, пока CLI-прототип с 3 этапами не работает на этой видеокарте.

## 6. Схема данных: единый источник истины

Внутренние результаты инференса и результаты ручного редактирования не смешивать. Хранить оригинальные данные и их редактируемое представление.

Пример (демонстрационный, не настоящая транскрипция):

```json
{
  "schema_version": 1,
  "project_id": "example-id",
  "media_path": "D:/Meetings/demo.mp4",
  "language": "ru",
  "duration_ms": 3600000,
  "speakers": [
    {"id": "spk_0", "display_name": "Спикер 1"},
    {"id": "spk_1", "display_name": "Спикер 2"}
  ],
  "segments": [
    {
      "id": "seg_1",
      "start_ms": 12300,
      "end_ms": 15400,
      "speaker_id": "spk_0",
      "text": "Коллеги, добрый день.",
      "words": [
        {"text": "Коллеги,", "start_ms": 12300, "end_ms": 13000, "speaker_id": "spk_0"},
        {"text": "добрый", "start_ms": 13200, "end_ms": 14400, "speaker_id": "spk_0"}
      ],
      "requires_review": false
    }
  ],
  "completed_stages": ["audio", "asr", "alignment", "diarization", "merge"]
}
```

Дополнительно: версии моделей и их hashes, когда запущено, путь к исходнику, код ошибок, исходные неизменённые сегменты, флаги неполного alignment, JSON backups. **Не сохранять аудио в SQLite.**

## 7. Пошаговая разработка в Codex

Каждый этап — отдельная задача/PR/коммит. **Codex сначала проверяет существующий код, пишет короткий план, затем реализует этап, запускает тесты и перечисляет изменённые файлы.** Не поручать ему построить всё приложение одним огромным запросом.

### Этап 0 — исследование и CLI proof of concept

**Задачи:**
- Создать репозиторий, venv, lock dependencies, минимальный `README`.
- Проверить cuda / torch / ctranslate2 на RTX 5070.
- Скачать модели с локальными абсолютными путями; зафиксировать manifest.
- Тест: один русский WAV с двумя говорящими: ASR → forced alignment → pyannote → сведения в JSON.
- Контроль VRAM после каждого этапа: последовательно удалять объекты моделей и очищать ненужные ресурсы (`gc.collect()`, `torch.cuda.empty_cache()`; последнее не заменяет удаление ссылок).
- Прогнать повторно без интернета.

**Критерий:** CLI выдаёт читаемый JSON с 2 условными спикерами, таймкодами и текстом, а запуск не требует Hugging Face токен в runtime.

### Этап 1 — доменная модель и медиаподготовка

**Задачи:**
- Описать `Project`, `Speaker`, `Segment`, `Word`, `TranscriptionJob`, `StageStatus`, версии схемы.
- Реализовать FFprobe проверку, FFmpeg извлечение в 16 kHz mono WAV и временную папку проекта.
- Поддержать символы кириллицы и пробелы в пути, запуск через `subprocess` со списком аргументов (не `shell=True`).
- Контроль прерывания, достаточного места, удаления временных файлов после успешного завершения.
- Протестировать короткое и длинное видео, только аудио, файл без аудиодорожки, битый контейнер, нестандартный кодек.

**Критерий:** из поддерживаемых файлов извлекается аудио, ошибки понятны, оригинал неизменён.

### Этап 2 — автономный ASR

**Задачи:**
- В `transcription.py` создать интерфейс `ASREngine` с загрузкой модели из локального пути.
- Реализовать режим ru + auto + en; `beam_size=5`, начально `compute_type=float16`, `batch_size=4` (настраиваемо).
- Предусмотреть VAD, ручной словарь терминов/подсказку для имён и аббревиатур без обещания гарантированного результата.
- Поэтапно записывать результат в проект; освобождать GPU после стадии.
- При OOM автоматически **однократно предложить** снизить batch/compute mode или повторить с профилем `Экономия памяти`, без бесконечных циклов.

**Критерий:** русский 15–30-минутный тестовый файл транскрибируется в локальный JSON, без сети.

### Этап 3 — временное выравнивание слов

**Задачи:**
- Реализовать `aligner` через русскую Wav2Vec2 с локальными `config`/`processor`/weights.
- По каждой фразе получить интервалы слов (в миллисекундах).
- Обрабатывать цифры, аббревиатуры, нераспознанные слова, тишину, выравнивание не всего сегмента.
- Если word alignment не удался: **не придумывать метки слов**, сохранить исходные интервалы сегмента и отметить `requires_review`.
- Не позволять отсутствующим меткам ломать экспорт.

**Критерий:** интервал сегмента и слова согласованы, отсутствующее выравнивание корректно помечается.

### Этап 4 — диаризация участников

**Задачи:**
- Создать `DiarizationEngine` на pyannote Community-1 с `Pipeline.from_pretrained(LOCAL_PATH)`, не облачным `precision-2`.
- Режим авто / точное число / диапазон числа говорящих.
- Записать интервалы речи спикеров, сохранить пересечения (overlap) и неопределённость.
- Сопоставить результаты с таймкодами слов, а не назначать спикера только всему исходному ASR-сегменту.
- При смене говорящего внутри одной фразы **разбивать отображаемый сегмент** на части.
- При невозможности уверенного назначения применять `unknown`, не выдумывать участника.
- Нумеровать `Спикер 1/2/3` по первому появлению в записи.
- Использовать `exclusive_speaker_diarization`, где это помогает синхронизировать интервалы, но не удалять сведения о реальном перекрытии речи.

**Критерий:** запись из двух-трёх говорящих размечена, смена в середине фразы корректно обрабатывается, пересечения не скрыты.

### Этап 5 — хранение проектов

**Задачи:**
- SQLite для перечня проектов и статусов, JSON для версионированных детальных результатов (или единая схема SQLite: решение обосновать и документировать).
- Автосохранение после каждой завершённой стадии и изменения редактора.
- История исправлений (минимум undo/redo внутри сессии), восстановление после аварийного завершения.
- При повторном открытии не запускать нейросети без команды пользователя.

**Критерий:** после закрытия приложения открывается существующая транскрипция с отредактированными спикерами.

### Этап 6 — PySide6 UI

**Экран импорта:** выбор/drag-and-drop файла, длительность, язык, число спикеров, профиль качества, кнопка `Начать`.

**Экран обработки:** текущее состояние, последовательность этапов, лог понятных ошибок, `Отменить`, `Повторить`.

**Экран редактора:** плеер, список фраз, таймкоды, выпадающий speaker, текстовое поле, подсветка текущего интервала, поиск, объединение/разделение, переименование всех появлений одного спикера, undo/redo, автосохранение.

**Настройки:** пути моделей, GPU/CPU, batch size, статус проверки offline assets, папка результатов, тема оформления, язык UI.

**Критерий:** приложение отзывчиво во время транскрибации, переходы и изменения не теряются.

### Этап 7 — экспорт TXT/DOCX/PDF

**Единый внутренний шаблон**: заголовок записи, дата обработки (не выдумывать дату совещания), исходный файл, продолжительность, язык, легенда спикеров, затем хронологические блоки `[HH:MM:SS] Имя: текст`.

**TXT:** UTF-8 с BOM по выбору для удобства открытия в старых Windows-программах, по умолчанию UTF-8; корректные переносы и кириллица.

**DOCX:** `python-docx`, заголовки, метаданные, стиль реплик, нумерация страниц, автоматическая разбивка длинных стенограмм; открывается в Word/LibreOffice.

**PDF:** ReportLab, TTF с кириллицей и правами на включение в установщик, перенос строк, повторяемые колонтитулы, корректная пагинация, отсутствие обрезки. **Не использовать системный Helvetica как единственный шрифт**.

**Настройки экспорта:** показывать/скрывать таймкоды, точность меток, имя спикера, разрыв между репликами, имя файла. Пользователь выбирает формат перед сохранением.

**Критерий:** один отредактированный проект даёт эквивалентный по содержанию TXT/DOCX/PDF, кириллица не повреждается.

### Этап 9 — производительность на Legion Pro 5

**Базовый профиль:** `large-v3`, `CUDA`, `float16`, batch 4, последовательная загрузка моделей, один worker. Если OOM: batch 2 → int8 профиль → CPU для отдельных компонентов.

**Измерения:** по каждому этапу записать wall-clock, максимальную загрузку VRAM, RAM и длительность аудио. Не выдумывать токены/сек или реальное время обработки: только замеры на устройстве.

**Сценарии:** 5 мин / 30 мин / 90 мин; 1/2/4 участника; шумный и чистый звук; отсутствие речи; смена speaker внутри фразы; пересечения, русские технические термины.

**Критерий:** отсутствие аварийного OOM и неприемлемого зависания UI, корректный результат при повторной обработке.

## 9. Технические риски

1. **CUDA/PyTorch/CTranslate2 на RTX 5070:** несовместимые версии и DLL — самая вероятная проблема первой установки. Решение: прототип и lock versions прежде GUI.
2. **WhisperX может иметь дополнительные VAD/ресурсы:** обязательно инвентаризировать и проверить офлайн.
3. **Видеоплеер Qt:** доступность кодеков зависит от Windows/QtMultimedia. При необходимости использовать конвертированную временную копию для плеера.
4. **Ошибки диаризации:** похожие голоса, музыка, пересечения, дистанционная запись искажённого звука. Нужен быстрый ручной редактор.
5. **Превышение VRAM:** модели только последовательно; memory-efficient профили; очищать ресурсы между фазами.
6. **PDF и шрифты:** нужна кириллица, embedding и проверка лицензий на дистрибуцию.
7. **Перепаковка в EXE:** большие бинарные зависимости, false positive антивируса, пути ресурсов, DLL. Проверять чистую установку и офлайн.
8. **Конфиденциальность:** пользовательские аудио, тексты и персональные данные должны оставаться локальными; временные WAV удалить только после завершения с учётом восстановления после сбоя.

# Local Transcriber — руководство пользователя

CLI подготавливает аудио из медиафайлов и распознаёт русскую и английскую речь.
Полная обработка русской речи использует Large V3, Russian Wav2Vec2 и
Community-1, затем сохраняет JSON версии 1 с временными метками и спикерами.
Результаты проверок описаны в [отчёте этапа 0](stage-0-report.md),
[отчёте этапа 1](stage-1-report.md), [отчёте этапа 2](stage-2-report.md) и
[отчёте этапа 3](stage-3-report.md), [отчёте этапа 4](stage-4-report.md) и
[отчёте этапа 5](stage-5-report.md).

## Подготовка

Требуется Windows x64, Python 3.11–3.13, совместимый драйвер NVIDIA и достаточно
свободного места для CUDA-библиотек и моделей. На этой машине используется
Python 3.13.12 и RTX 5070 Laptop 8 ГБ. Установка библиотек, FFmpeg и моделей
выполняется с интернетом по `docs/offline-install.md`. После проверки GPU
используйте зафиксированный `requirements.lock`. Данные пользователя не
передаются при подготовке или распознавании.
Lock-файл проверен на Windows/Python 3.13; отдельные прогоны на 3.11–3.12
не выполнялись.

Модели хранятся в `%USERPROFILE%\.lmstudio\models\local-transcriber`:
`whisper-large-v3`, `wav2vec2-ru`, `pyannote-community-1`, `vad`, `nltk_data`.
LM Studio запускать не требуется. Пути задаются в исключённом из Git
`config.local.json`; образец — `config.example.json`. Все пути к моделям и
FFmpeg/ffprobe должны быть абсолютными локальными путями.

Для первоначального скачивания Community-1 примите условия модели на Hugging
Face и запустите `scripts\prepare_community.ps1`: Read-токен вводится скрыто,
используется только временно и не сохраняется скриптом. При обработке токен
не нужен. Не отправляйте токены в чат и не записывайте их в `.env`.

## Подготовка только аудио

```powershell
.\.venv\Scripts\python.exe -m local_transcriber --config .tools/ffmpeg-install.json prepare-media 'sample\Дуэт Да.mp4' --run-dir artifacts\my-audio
```

Команде достаточно FFmpeg/ffprobe и файла конфигурации с их абсолютными путями.
Она извлекает первую аудиодорожку в `audio.wav` в новом каталоге и сообщает
длительность, исходный кодек и число каналов. Результат имеет формат PCM 16 бит,
16 кГц, один канал. Нужное место оценивается по длительности, с резервом 16 МиБ.
Для каждого запуска укажите новый каталог на локальном диске.

При Ctrl+C во время медиаподготовки FFmpeg/ffprobe останавливается, частичный
WAV удаляется. При ошибке смотрите `error_code` и `hint` в терминале.
`NO_AUDIO_STREAM` означает отсутствие дорожки, `INVALID_MEDIA` — контейнер
не удалось прочитать, `INSUFFICIENT_DISK_SPACE` — на диске мало места.
Для WAV, превышающего предел формата около 4 ГиБ, разделите запись на части.

## Транскрибация записи

Для распознавания речи без выравнивания и разделения спикеров:

```powershell
.\.venv\Scripts\python.exe -m local_transcriber --config config.local.json asr 'sample\Дуэт Да.mp3' --language auto --run-dir artifacts\my-asr
.\.venv\Scripts\python.exe scripts\check_run.py artifacts\my-asr --asr-only --expected-language ru
```

Для `asr` доступны `--language ru` (по умолчанию), `en` и `auto`.
В режиме `auto` WhisperX определяет язык по началу записи. Достаточно путей к
Large V3, VAD, манифесту, FFmpeg и ffprobe в конфигурации. В `transcript.json`
указаны язык, текст и интервалы сегментов в миллисекундах. В этом режиме
спикеры имеют значение `unknown`, а список слов с таймкодами пуст.
`asr.json` содержит исходный результат распознавания.

Перед распознаванием CLI сохраняет состояние проекта после медиаподготовки.
После ASR обновляет JSON с текстом. Если следующий шаг полной обработки
завершится ошибкой, результат ASR остаётся доступен.

Для обоих режимов можно передать `--terms-file artifacts\terms.txt`.
Укажите по одному имени, термину или аббревиатуре в строке UTF-8 файла
размером до 4096 байт. Слова служат подсказкой модели. Она может пропустить
подсказку или ошибиться в написании. Храните файл в локальном каталоге,
исключённом из Git.

Для распознавания, выравнивания и разделения спикеров используйте `transcribe`.
Язык этой команды — русский.

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts\diagnose.py
.\.venv\Scripts\python.exe -m local_transcriber --config config.local.json verify-models
.\.venv\Scripts\python.exe -m local_transcriber --config config.local.json transcribe 'sample\Дуэт Да.mp3' --run-dir artifacts\my-run
.\.venv\Scripts\python.exe scripts\check_run.py artifacts\my-run --expected-speakers 2
```

Для MP4 замените входной путь. Используйте новый `--run-dir` при каждом запуске.
Рабочий WAV удаляется после успешного сохранения транскрипции. После сбоя
модели полностью извлечённый WAV остаётся в каталоге вместе с промежуточными
данными для диагностики. Повторный запуск обрабатывает запись заново.

В каталоге результата находятся `transcript.json` с текстом, словами,
временем в миллисекундах и условными спикерами, исходные `asr.json`,
`alignment.json`, `diarization.json` и технический `metrics.json` со статусами
фаз. Каталоги с конфиденциальными данными `sample/` и `artifacts/` исключены из
Git. В метриках и сообщениях CLI есть только технические сведения.

Настройки ASR по умолчанию — CUDA, `float16`, `batch_size=4`, `beam_size=5`.
Изменить `batch_size` и `compute_type` можно в конфигурации.
При нехватке памяти GPU CLI сообщает
`ASR_GPU_OUT_OF_MEMORY` и один раз предлагает повторить команду вручную с
`--profile memory` и новым `--run-dir`. Профиль ограничивает батч двумя
элементами и использует `int8_float16` на CUDA или `int8` на CPU.
Модель остаётся Large V3. В этапе 2 проверен профиль экономии на CUDA.

Русский Wav2Vec2 ставит метки слов в пределах фразы. Для слов с цифрами или
буквами вне словаря модели, пометок вроде `[неразборчиво]` и слов без
подтверждённого интервала поля `start_ms` и `end_ms` имеют значение `null`. У таких слов
установлен `alignment_missing`. Исходный текст, интервал и пригодные метки
слов остаются в `original_alignment`. Флаг `requires_review` и причина
`alignment_incomplete` указывают на неполное выравнивание.

## Спикеры и перекрытия

Число говорящих для `transcribe` задаётся в локальном JSON-конфиге.

- Точное число. Укажите `"num_speakers": 2`, это значение по умолчанию.
- Авто. Укажите `"num_speakers": null`. Community-1 оценит число говорящих.
- Диапазон. Укажите `"min_speakers": 2, "max_speakers": 3`. Оставьте
  `"num_speakers": null` или удалите это поле. Границы должны быть
  положительными целыми, нижняя граница может совпадать с верхней.

Номера «Спикер 1», «Спикер 2» назначаются по первому появлению голоса.
Код сопоставляет спикеров с интервалами слов и разбивает фразу при смене
говорящего. При неоднозначности слово получает `unknown` и пометку проверки.
Слово с пропущенной меткой остаётся `unknown` даже в разбитой фразе.

В `transcript.json` поле `diarization_turns` содержит исходную разметку с
возможными пересечениями, `exclusive_diarization_turns` — дорожку, в которой
одновременно представлен один голос. Обе дорожки используют секунды.
`overlap_regions` содержит границы в миллисекундах и ID спикеров, которые
модель обнаружила одновременно. Эксклюзивная дорожка может содержать меньше
спикеров, чем исходная. В `diarization.json` обе дорожки сохранены в полях
`turns` и `exclusive_turns`. Смех может влиять на назначение говорящего.
Оценка WER/CER/DER требует ручного эталона.

## Сохранённые проекты

`asr` и `transcribe` автоматически записывают проект в `projects.sqlite3`
рядом с каталогом `--run-dir`. Для обычного каталога `artifacts\my-run`
это `artifacts\projects.sqlite3`. Сохранение происходит после каждой
завершённой фазы. Запись с пометкой `incomplete` содержит последнюю
сохранённую фазу, в том числе после аварийного выхода.

```powershell
.\.venv\Scripts\python.exe -m local_transcriber projects list
.\.venv\Scripts\python.exe -m local_transcriber projects open PROJECT_ID --output artifacts\reopened.json
.\.venv\Scripts\python.exe -m local_transcriber projects import artifacts\old-run\transcript.json
```

Подставьте ID из списка. Для открытия используется SQLite и создаётся новый
JSON-файл. Импорт принимает JSON версии 1 с новым для этой базы ID. Если
используете другую базу, передайте `--project-db ПУТЬ` перед командой
`asr`, `transcribe` или `projects`. Держите базу и копии JSON в локальном
каталоге, исключённом из Git.

Для правок сохраните команды в файле UTF-8 по одному JSON-объекту на строку:

```jsonl
{"op":"rename_speaker","speaker_id":"spk_0","display_name":"Ведущая"}
{"op":"set_segment_speaker","segment_id":"seg_1","speaker_id":"unknown"}
{"op":"undo"}
{"op":"redo"}
```

```powershell
.\.venv\Scripts\python.exe -m local_transcriber projects edit PROJECT_ID --commands artifacts\edits.jsonl
```

Команда `set_segment_text` принимает `segment_id` и `text`. Она сохраняет
интервал сегмента и убирает его устаревшие метки слов. Исходные результаты
моделей остаются в проекте. Без `--commands` команды читаются из стандартного
ввода. Каждая правка сохраняется сразу, включая undo и redo. Стеки отмены и
повтора доступны в текущей сессии. При открытии доступны правки из последней
сохранённой версии. Команды `projects` работают без конфигурации моделей и
запуска распознавания.

## Проверка без интернета

Runtime всегда включает офлайн-флаги и блокировку Python socket/DNS API.
Для подтверждения блокировки на уровне ОС:

```powershell
.\.venv\Scripts\python.exe scripts\verify_offline.py --config config.local.json --input 'sample\Дуэт Да.mp4' --run-dir artifacts\my-offline-run
.\.venv\Scripts\python.exe scripts\verify_offline.py --config config.local.json --asr-only --language auto --input 'sample\Дуэт Да.mp4' --run-dir artifacts\my-offline-asr
```

Скрипт проверяет Windows AppContainer без сетевых разрешений и прямые
подключения до включения блокировки Python. В изолированной среде Codex
это позволяет реально проверить весь pipeline без сети. В обычном PowerShell
скрипт вернёт код 3, если такую изоляцию доказать нельзя. Текущая версия
распознаёт только AppContainer; отключение адаптера или внешний firewall
требуют отдельной проверки. Одних офлайн-флагов недостаточно для отметки
об успешной проверке ОС.

Код `0` означает успех, `1` — ошибку обработки, `2` — ошибку
конфигурации, проверки или входа, `130` — прерывание Ctrl+C. `verify_offline.py`
возвращает `3` без доказанной изоляции, иначе код CLI. `check_run.py`
возвращает `0` при успешной структурной проверке или `1` при ошибках.

Замеры VRAM относятся ко всей видеокарте, включая другие приложения, и
снимаются периодически; краткий пик может быть пропущен. Torch-метрика
выделенной памяти не включает CTranslate2. Фактические время, RSS и VRAM
смотрите в `metrics.json` конкретного запуска.

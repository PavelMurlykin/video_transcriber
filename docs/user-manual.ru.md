# Local Transcriber — руководство пользователя

CLI подготавливает аудио из медиафайлов и транскрибирует русскую речь. Полная
обработка использует Large V3, Russian Wav2Vec2 и Community-1, затем сохраняет
JSON версии 1 с временными метками и спикерами. Результаты проверок доступны в
[отчёте этапа 0](stage-0-report.md) и [отчёте этапа 1](stage-1-report.md).

## Подготовка

Требуется Windows x64, Python 3.11–3.13, совместимый драйвер NVIDIA и достаточно
свободного места для CUDA-библиотек и моделей. На этой машине используется
Python 3.13.12 и RTX 5070 Laptop 8 ГБ. Установка библиотек, FFmpeg и моделей
выполняется с интернетом по `docs/offline-install.md`. После проверки GPU
используйте зафиксированный `requirements.lock`. Данные пользователя не
передаются при подготовке или распознавании.
Lock-файл проверен на Windows/Python 3.13; отдельные прогоны на 3.11–3.12
не выполнялись.

Модели хранятся в `%USERPROFILE%\.lmstudio\models\local-transcriber`:
`whisper-large-v3`, `wav2vec2-ru`, `pyannote-community-1`, `vad`, `nltk_data`.
LM Studio запускать не требуется. Пути задаются в исключённом из Git
`config.local.json`; образец — `config.example.json`. Все пути к моделям и
FFmpeg/ffprobe должны быть абсолютными локальными путями.

Для первоначального скачивания Community-1 примите условия модели на Hugging
Face и запустите `scripts\prepare_community.ps1`: Read-токен вводится скрыто,
используется только временно и не сохраняется скриптом. При обработке токен
не нужен. Не отправляйте токены в чат и не записывайте их в `.env`.

## Подготовка только аудио

```powershell
.\.venv\Scripts\python.exe -m local_transcriber --config .tools/ffmpeg-install.json prepare-media 'sample\Дуэт Да.mp4' --run-dir artifacts\my-audio
```

Команде достаточно FFmpeg/ffprobe и файла конфигурации с их абсолютными путями.
Она извлекает первую аудиодорожку в `audio.wav` в новом каталоге и сообщает
длительность, исходный кодек и число каналов. Результат имеет формат PCM 16 бит,
16 кГц, один канал. Нужное место оценивается по длительности, с резервом 16 МиБ.
Для каждого запуска укажите новый каталог на локальном диске.

При Ctrl+C во время медиаподготовки FFmpeg/ffprobe останавливается, частичный
WAV удаляется. При ошибке смотрите `error_code` и `hint` в терминале.
`NO_AUDIO_STREAM` означает отсутствие дорожки, `INVALID_MEDIA` — контейнер
не удалось прочитать, `INSUFFICIENT_DISK_SPACE` — на диске мало места.
Для WAV, превышающего предел формата около 4 ГиБ, разделите запись на части.

## Транскрибация записи

Из корня проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe scripts\diagnose.py
.\.venv\Scripts\python.exe -m local_transcriber --config config.local.json verify-models
.\.venv\Scripts\python.exe -m local_transcriber --config config.local.json transcribe 'sample\Дуэт Да.mp3' --run-dir artifacts\my-run
.\.venv\Scripts\python.exe scripts\check_run.py artifacts\my-run --expected-speakers 2
```

Для MP4 замените входной путь. Используйте новый `--run-dir` при каждом запуске.
Рабочий WAV удаляется после успешного сохранения транскрипции. После сбоя
модели полностью извлечённый WAV остаётся в каталоге вместе с промежуточными
данными для диагностики. Повторный запуск обрабатывает запись заново.

В каталоге результата находятся `transcript.json` с текстом, словами,
временем в миллисекундах и условными спикерами, исходные `asr.json`,
`alignment.json`, `diarization.json` и технический `metrics.json` со статусами
фаз. Каталоги с конфиденциальными данными `sample/` и `artifacts/` исключены из
Git. В метриках и сообщениях CLI есть только технические сведения.

Профиль по умолчанию: русский язык, CUDA, `float16`, `batch_size=4`,
`beam_size=5`, `num_speakers=2`. Для автоматического числа спикеров задайте
`num_speakers: null`. При нехватке памяти можно явно выбрать `batch_size: 2`,
затем `compute_type: "int8_float16"`, либо `device: "cpu"` с
`compute_type: "float32"`. Модель остаётся Large V3. Автоматического повторения
после OOM и скрытого перехода на CPU нет; изменение профиля требует повторной
проверки. CPU может работать значительно медленнее.
Альтернативные профили CPU/int8 в этапе 0 отдельно не проверялись.

Неполное выравнивание, смена спикера и перекрытие речи обозначаются
`requires_review` и причинами проверки. Отсутствующие времена слов — `null`;
неопределённый спикер — `unknown`. Смех не классифицируется отдельным событием
и может ухудшить распознавание или назначение говорящего. Имена людей не
определяются. WER/CER/DER без ручного эталона не измеряются.

## Проверка без интернета

Runtime всегда включает офлайн-флаги и блокировку Python socket/DNS API.
Для подтверждения блокировки на уровне ОС:

```powershell
.\.venv\Scripts\python.exe scripts\verify_offline.py --config config.local.json --input 'sample\Дуэт Да.mp4' --run-dir artifacts\my-offline-run
```

Скрипт проверяет Windows AppContainer без сетевых разрешений и прямые
подключения до включения блокировки Python. В изолированной среде Codex
это позволяет реально проверить весь pipeline без сети. В обычном PowerShell
скрипт вернёт код 3, если такую изоляцию доказать нельзя. Текущая версия
распознаёт только AppContainer; отключение адаптера или внешний firewall
требуют отдельной проверки. Одних офлайн-флагов недостаточно для отметки
об успешной проверке ОС.

Код `0` означает успех, `1` — ошибку обработки, `2` — ошибку
конфигурации, проверки или входа, `130` — прерывание Ctrl+C. `verify_offline.py`
возвращает `3` без доказанной изоляции, иначе код CLI. `check_run.py`
возвращает `0` при успешной структурной проверке или `1` при ошибках.

Замеры VRAM относятся ко всей видеокарте, включая другие приложения, и
снимаются периодически; краткий пик может быть пропущен. Torch-метрика
выделенной памяти не включает CTranslate2. Фактические время, RSS и VRAM
смотрите в `metrics.json` конкретного запуска.

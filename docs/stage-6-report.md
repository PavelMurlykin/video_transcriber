# Этап 6. Настольный клиент

27.11.2026. Настольный клиент проверен на Windows с Python 3.13.12, PySide6
6.12.0 и RTX 5070 Laptop. Критерий этапа проверяется переключением вкладок
во время обработки и восстановлением правки после закрытия окна.

Клиент запускает существующую CLI-команду через асинхронный `QProcess`.
Распознавание, выравнивание и диаризация выполняются в отдельных процессах,
как в этапах 0–5. Qt получает метаданные медиа, коды ошибок и события
стадий. При отмене CLI останавливает текущий процесс и сохраняет последний
успешный снимок в SQLite. Повтор запуска создаёт новый каталог. Редактор
работает с сохранённым снимком и сохраняет правки в ту же базу.

Русский режим использует полный цикл. Автоопределение языка и английский
используют только ASR, поскольку установленный Wav2Vec2 выравнивает русскую
речь. Профиль экономии памяти использует настройки существующей команды ASR.

## Проверки и замеры

| Проверка | Фактический результат |
|---|---|
| Регрессионные тесты | 85 тестов прошли за 6,64 с, включая Qt-импорт, настройки, редактор и автосохранение |
| Интеграционный тест в Windows AppContainer | 1 тест прошёл за 148,52 с. Использовалась оконная платформа Qt `windows` |
| Запуск окна Windows | Основное окно отобразилось, доступны четыре вкладки |
| Полный прогон MP4 из окна | 58,839 с аудио обработаны за 134,23 с от нажатия кнопки до результата. Два спикера, 33 сегмента и 10 областей перекрытия. `check_run.py` не обнаружил ошибок в JSON |
| Отзывчивость | Вкладка переключалась во время ASR, прогресс обновлялся. Максимальный интервал таймера Qt составил 85 мс при заданном интервале 50 мс |
| Потребление памяти | До 6040 МиБ общей VRAM и 3,58 ГиБ RSS дерева процессов инференса на ASR |
| Изоляция Windows AppContainer | Сетевые возможности отсутствовали. Две прямые TCP-пробы отклонены с `WinError 10013`, DNS недоступен |
| Отмена и повтор в окне | Отмена на старте ASR заняла 257 мс. Снимок после подготовки аудио остался в каталоге со статусом `cancelled`. Повтор завершился в новом каталоге |
| Воспроизведение в обычном окне Windows | MP4 H.264/AAC и MP3 открылись без сети. Проверены переход по таймкоду, пауза, выделение фразы и скорость 1,25×. Получены звуковые буферы обоих форматов и кадры MP4 |
| Восстановление редактора | Текст сохранён при закрытии окна. Новое окно открыло изменённый проект без инференса |
| Состояние зависимостей и синтаксиса | `pip check` и `compileall` прошли |

Проверка звука выполнена по декодированным буферам. Qt видел аудиоустройство,
субъективное прослушивание не проводилось. VRAM измеряется для всей видеокарты.
RSS процесса интерфейса не входит в дерево процессов инференса. Подтверждение
сетевой изоляции запуска из Qt записано отдельным тестом в `network.json`.

## Ошибки и исправления

- Первичный `pip check` обнаружил зависимости общего пакета PySide6
  от Qt WebEngine и Qt PDF. В `requirements-ui.lock` оставлены используемые
  пакеты Essentials, Addons и Shiboken6 версии 6.12.0 с SHA-256. Повторная
  установка из локальных wheel-файлов и `pip check` прошли.
- В первых проверках перезагруженная конфигурация смешивала настройки
  инференса и поля окна. Поля разделены, регрессионный тест проходит.
- Qt Multimedia выводил сведения о контейнере и путь источника.
  Подробный вывод отключён при старте приложения. Проверка MP4 и MP3
  с унаследованным флагом отладки прошла без вывода метаданных.
  [Конфигурация журналирования Qt](https://doc.qt.io/qt-6.12/advanced-ffmpeg-configuration.html)
- На выходе из отдельных успешных запусков `pyreadline3` сообщил об ошибке
  дескриптора консоли `0xc0000008`. Код выхода pytest остался 0.

Команды приёмки приведены в [описании тестов](testing.md). Приватные результаты
и метрики находятся в игнорируемом каталоге `artifacts/`. Обновлены
[русское](user-manual.ru.md) и [английское](user-manual.en.md) руководства.
